## 1. Neon Database Architecture & Connection Setup

The backend connects to a hosted Neon serverless PostgreSQL instance.

- **Connection Driver**: `psycopg` (psycopg3 binary driver)
- **URL Schema**: `postgresql+psycopg://neondb_owner:***@ep-quiet-fire-axz8pyxt-pooler.c-4.us-east-2.aws.neon.tech/neondb?sslmode=require`
- **Environment Management**: Defined in `.env` (uncommitted) and sanitized in `.env.example`.

### Connection Pooling Strategy

Configured in `app/database.py` for cloud resilience:

```python
engine = create_engine(
    DATABASE_URL,
    pool_pre_ping=True,  # Verifies socket liveness before returning connection to caller
    pool_size=5,         # Maintains persistent pool of up to 5 connections
    max_overflow=10,     # Allows temporary overflow up to 10 connections under load
    pool_recycle=300,    # Recycles idle connections every 5 minutes
)
```

## 2. Database Entity Models & Relational Schema

### 2.1 Table: `junctions`

Stores monitored traffic intersections across Nagpur.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` | Primary Key, Autoincrement, Index | Unique Junction ID |
| `name` | `VARCHAR(255)` | Not Null, Index | Junction Name (e.g. Sitabuldi Interchange) |
| `latitude` | `FLOAT` | Not Null | Latitude Coordinate (WGS84) |
| `longitude` | `FLOAT` | Not Null | Longitude Coordinate (WGS84) |
| `address` | `VARCHAR(500)` | Nullable | Location / Area Address |
| `created_at` | `TIMESTAMPTZ` | Not Null, Default `now()` | Record Creation Timestamp |

---

### 2.2 Table: `traffic_observations`

Stores raw traffic telemetry data captured for junctions.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` | Primary Key, Autoincrement, Index | Unique Observation ID |
| `junction_id` | `INTEGER` | Foreign Key (`junctions.id` ON DELETE CASCADE), Index | Associated Junction |
| `timestamp` | `TIMESTAMPTZ` | Not Null, Index | Observation Timestamp |
| `traffic_data` | `JSONB` | Not Null | Flexible Key-Value Traffic Features |
| `created_at` | `TIMESTAMPTZ` | Not Null, Default `now()` | Record Creation Timestamp |

---

### 2.3 Table: `predictions`

Stores ML prediction outputs generated by the backend.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` | Primary Key, Autoincrement, Index | Unique Prediction ID |
| `junction_id` | `INTEGER` | Foreign Key (`junctions.id` ON DELETE SET NULL), Index | Associated Junction |
| `timestamp` | `TIMESTAMPTZ` | Not Null, Index | Prediction Timestamp |
| `prediction` | `VARCHAR(255)` | Not Null | Predicted Output Class / Risk Value |
| `probability` | `FLOAT` | Nullable | Confidence Score / Probability |
| `is_mock` | `BOOLEAN` | Nullable, Default `False` | True if generated by Dev Mock Adapter |
| `features_used` | `JSONB` | Nullable | Features Evaluated by ML Model |
| `created_at` | `TIMESTAMPTZ` | Not Null, Default `now()` | Record Creation Timestamp |

- A single `Junction` supports multiple `Prediction` records.
